# A1 Анализ линейного пробирования

## 1.1 Проблема в алгоритмах

Из-за того, что используем ``ERASED`` отличный от ``NULL``, при множественной вставке, а затем удалении
большинства элементов можем получить ситуацию, когда поиск элемента перед множеством удаленных будем занимать много
времени.
Также возможна ситуация, когда вставка будет занимать много времени из-за большого числа ``Erased``

---

## 1.2 Пример

``M = 10``, ``hash(k) = k mod M``

1. INSERT(0) -> позиция 0
2. INSERT(10) -> коллизия с 0, позиция 1
3. INSERT(20) -> коллизия с 0, позиция 2
4. INSERT(30) -> коллизия с 0, позиция 3
5. DELETE(0) -> позиция 0 = ERASED
6. DELETE(10) -> позиция 1 = ERASED
7. DELETE(20) -> позиция 2 = ERASED

Таблица: [ERASED, ERASED, ERASED, 30, NULL, NULL, NULL, NULL, NULL, NULL]

Теперь SEARCH(40):
hash(40) = 0

1. table[0] = ERASED != NULL -> ind = 1
2. table[1] = ERASED != NULL -> ind = 2
3. table[2] = ERASED != NULL -> ind = 3
4. table[3] = 30 != 40 -> ind = 4
5. table[4] = NULL -> return false

Прошли 4 ячейки при поиске, хотя всего 1 занята.

Если в этой же ситуации захотим вставить элемент в начало последовательности `ERASED` - INSERT(50), то придется идти 5
ячеек от нуля.

Кроме того возможна ситуация бесконечного цикла, если таблица полностью заполнены и мы пытаемся сделать любую операцию с
ключом, которого нет в таблице:
``M = 3``, ``hash(k) = k mod M``

1. INSERT(0) -> позиция 0
2. INSERT(1) -> позиция 1
3. INSERT(2) -> позиция 2
4. INSERT(3) -> коллизия с 0
5. Условие `table[ind] != NULL` всегда верно, а return никогда не выполняется

---

## 2. Доработки алгоритмов.

### 2.1 Первая проблема

Для решения первой проблемы можно использовать следующий вариант `DELETE`:

```c++
DELETE(key):
    ind = hash(key) mod M
    
    while (table[ind] != NULL)
        if (table[ind] == key)
            break
        ind = (ind + 1) mod M
    
    if (table[ind] == NULL) return
    
    // Удаляем ключ
    table[ind] = ERASED
    
    // "Подтягиваем" последующие элементы при необходимости
    next_ind = (ind + 1) mod M
    while (table[next_ind] != NULL)
        // Проверяем, должен ли этот элемент быть на текущей позиции
        correct_pos = hash(table[next_ind]) mod M
        
        // Если элемент должен находиться в позиции ind или раньше в цепочке
        // (с учетом зацикливания таблицы)
        should_move = false
        if (ind >= correct_pos)
            // Обычный случай: correct_pos <= ind < next_ind
            should_move = (correct_pos <= ind && ind < next_ind)
        else
            // Случай с зацикливанием: ind < next_ind <= correct_pos
            // или correct_pos <= ind < next_ind
            should_move = (next_ind > ind && (correct_pos <= ind || correct_pos >= next_ind))
        
        if (should_move)
            table[ind] = table[next_ind]
            table[next_ind] = ERASED
            ind = next_ind
        else
            break
        
        next_ind = (ind + 1) mod M
    
    // Очищаем последнюю ERASED ячейку, если нет элементов для подтягивания
    if (table[next_ind] == NULL)
        table[ind] = NULL
```

### 2.2 Вторая проблема

Для решения второй ситуации можем немного изменить INSERT:

```c++
INSERT(key):
    ind = hash(key) mod M
    
    while(table[ind] != NULL && table[ind] != ERASED)
        if (table[ind] == key) return
        ind = (ind + 1) mod M
    
    table[ind] = key
```

Теперь можем вставлять на место `ERASED` уменьшая длину цепочек проверок.

### 2.3 Третья проблема

Для решения третьей проблемы сделаем проверку на полный обход таблицы. Код на примере `SEARCH`:

```c++
SEARCH(key):
    ind = hash(key) mod M
    start_ind = ind  // Запоминаем начальную позицию
    
    while (table[ind] != NULL)
        if (table[ind] == key)
            return true
        ind = (ind + 1) mod M
        // Проверяем, не прошли ли мы полный круг
        if (ind == start_ind)
            break  // Прошли всю таблицу, ключа нет
    
    return false
```
